## 1. 决策

1. **v1.0 不含向量检索**：`T3-08`–`T3-11` **暂缓执行**（不取消）。
2. 向量在**后续版本**以**可选后端**形式引入：**默认关闭**，未配置时行为与 v1 完全一致（纯 BM25）；必须以 opt-in 的依赖/配置进入，**不得成为 v1 的安装前置**。
3. **`ADR-14` 的 R2 事实判断不被推翻**——"纯词法够不到 `A5`（零词法重叠）类查询"仍然成立。本条只改执行安排。
4. **M3 视为"决策已闭合"**：问题已回答（S3 有提升、R2 命中）、裁决已做；**执行被显式推迟**到后续版本。

> **后续更新（2026-09-23）**：本节四条里，**第 1 条的"暂缓"已结束**——`T3-08`–`T3-11` **已重启**（`ADR-16`）。第 2 条的形态要求（默认关闭、未配置时与 v1 一致、不得成为安装前置）被 `ADR-16` §1–§3 逐条冻结成**可验收**条文；第 3 条的 R2 事实判断不变；第 4 条的"M3 决策已闭合"也不变——**重启的是执行，不是重开决策门**。

## 2. 依据（事先写下，避免事后找理由）

### 2.1 端到端目标已由**纯词法 + 工具采纳**达成

| 证据 | 数值 |
|---|---|
| S3（A 组无检索 vs B 组词法） | 0.308 → **0.897（+59.0pp）**，门禁 0 回归 |
| 采纳率（按 attempt） | 33.3% → 79.5%（R5：只改 `code_search` 的 `description`） |
| **调用了工具的 31 个 attempt** | **只失败 1 个** |
| 残余 4 条失败 | **3 条未采纳 + 1 条步数超限**，**0 条归因于检索排序** |

→ 向量对 **S3 没有可测量的需求**。

### 2.2 结构手段已被实测排除

分块修复实验（gap 加行数上限 + TS `type`/`const` 纳入声明）：结构确实改善（最大单块 **3302 → 200 行**、gap **68.0% → 65.5%**、新增 2647 个声明块），但 **S1/S2 逐条零变化**（0 改善 / 0 回归），只有 S4 token 中位数 2492 → 2341。

→ 17 条 miss **全部是 `A5`**。分块改的是"以什么粒度被检索"，而 A5 是"查询与代码没有共同词元"——**失败在词表，不在粒度**。

### 2.3 S1/S2 达标的门槛比看上去更高

- S1 要求 `S@5 ≥ 0.80` = **24/30 命中**；当前 13（exact 12 + crossfile 1）。
- 三桶**刚刚达标**的合计只有 **22/30 = 0.733**，所以 **S1 严于"分桶阈值全达标"**。
- 要达标必须把 **`crossfile` 从 1/11 拉到 8–9/11**——那是**比 `natural` 更大的桶**。

### 2.4 部署代价与 v1 目标冲突

`ADR-14` 选的方案要求**用户**：装 Ollama（系统级服务）+ 下载 `bge-m3` **1.2 GB**（[官方页面](https://ollama.com/library/bge-m3)）+ 每仓库约 **258 MB** 向量 + 首次索引**几十分钟**。这与 v1 的"clone + `pip install .` + 一个 YAML、零 install script、默认不联网"直接冲突，也与"先让社区装得上"冲突。云端 embedding 需 API key，违反 `S-01`（默认不联网），不采用。

## 3. 重启条件（**事先写下**）

向量作为**可选后端**重启时，必须同时满足：

1. **形态**：默认关闭 + opt-in；未配置时干净退回 BM25；**不得进入 v1/后续版本的必需依赖**（打包、安装脚本、README 前置条件）。
2. **先跑向量天花板探针**：对 30 条 query + 全量 chunk 做一次 embedding，测 `natural`/`crossfile` 的 S@5/MRR 上限，**用数据决定是否值得全量实施**。
3. 若实施，按 **`ADR-14` §10.4 的 V1–V4**：V1 主判据是 `natural` S@5；V2 `exact` 保持 1.000 且零单条回归（由 `T3-12` 门禁执行）；V3 C vs B 按 `EVAL.md` §2.6 第二轮 **α = 0.025**；V4 **C 组若不能显著优于 B 组，就不发布向量路径**。
4. `T3-11` 的验收命令需先更新——现文本引用已废弃的 `dsh-eval-harness` API（`eval_run(...)`），应改为自建 runner `scripts/ab_eval.py run --patch <vector patch>`。

> **后续更新（2026-09-23）**：本节四条重启条件**已逐条兑现**——① 形态由 `ADR-16` §1/§2 冻结（默认关闭、干净回退、不进必需依赖）；② "先跑天花板探针"由 `T5-14` 执行，**先有数据再决定是否全量实施**；③ V1–V4 由 `ADR-16` §7.2 逐条继承（V3 仍是 **α = 0.025**，V4 仍是"C 不显著优于 B 就不发布"）；④ `T3-11` 的验收命令已换成自建 runner：`CODERAG_SEMANTIC=on python scripts/ab_eval.py run --cases cases --group eval-coderag-vector --out eval/runs/c-v1 --profile headless --patch cordis.patch.yml --workspace <语料副本> --trials 3`。

## 6. 诚实的限制

1. **样本小**：30 条、13 条命中，`natural` 只有 7 条；`A5` 占比高**部分是诊断配比造成的**，不代表真实流量。
2. **"向量无用"并未被证明**：本条只主张"当前证据不足以支撑 v1 引入"以及"重启前先用探针验证"。若探针显示 `natural` 大幅改善，应**重开本条**。
3. **S1/S2 未达标意味着引擎单独看仍不合格**：v1 的定位是"接进 Agent 后有用"，不是"检索质量达标"。对外表述不得混淆这两件事。
