## 为什么用 DSH 仓库本身做例子

`EVAL.md` §2.4 列了三个候选仓库。这里的例子选了 **DSH 本身**，因为：

1. **你能立刻验证每条 `expect_paths` 是否真的正确**——打开文件看一眼即可
2. **跨文件关系真实且丰富**（13 个功能组、284 个包）
3. **它就是你要检索的目标仓库**，拿它练手等于直接为 M1 做准备

## 10 条的设计意图（**这部分比 JSONL 本身更重要**）

### `exact` 桶（4 条）—— regression 用，**预期接近满分**

| ID | 查什么 | 为什么选它 |
|---|---|---|
| `L-001` | `SEARCH_RAW_OUTPUT_OVERFLOW` | 独特错误码。**这条失败 = 你的索引/分词有 bug，与"要不要向量"无关**。这是诊断基线 |
| `L-002` | `deriveMessages` | 跨两个包都有定义。检验**索引是否覆盖全部 workspace**，而不是只索引了某个子目录 |
| `L-003` | `toolCallTimeoutMs` | schema 定义与实际使用分处两个文件。同时它是**约束 E-01（60s 超时）的代码出处** |
| `L-004` | `sandbox/mode` | **含斜杠**。检验非字母字符不会破坏你的 FTS5 查询构造（`MATCH` 语法对特殊字符敏感） |

### `crossfile` 桶（4 条）—— 项目的核心价值

| ID | 查什么 | 为什么选它 |
|---|---|---|
| `L-005` | MCP 工具如何进入模型工具表 | 概念横跨 **mcp-client（适配）+ core/tools（注册表）**。只返回一个算部分命中 |
| `L-006` | 压缩在哪触发、在哪实现 | 触发点在 `agent-loop`，实现在 `compaction-basic`。**典型的"模型猜不到第二个文件"场景** |
| `L-007` | 会话被硬中断后怎么修复 | 机制名不出现，答案在 `repair.ts` |
| **`L-008`** | **插件发现机制写在哪** | ⚠️ **故意设的陷阱**——答案在仓库根的 **Markdown 文件**，而第一版索引器**只索引代码扩展名**。**这条预期会失败**，它存在的意义是让你在 M2 决定要不要把 `.md` 纳入索引 |

### `natural` 桶（2 条）—— **唯一可能支持"上向量"的证据来源**

| ID | 查什么 | 为什么选它 |
|---|---|---|
| `L-009` | 工具输出过长时怎么处理 | 零标识符，两个机制（spill + 结果裁剪）都算对，**不指定唯一答案** |
| **`L-010`** | **模型生成被打断时留下什么记录** | 零标识符。**本集合里最可能需要向量的一条**——如果 BM25 在它上面失败、且归因为 `A5`（零词法重叠），才构成上向量的证据 |

## 这份示例**故意不完美**——三处刻意的设计

| # | 设计 | 目的 |
|---|---|---|
| 1 | `L-008` 的答案在 Markdown 里 | 制造一条**预期的失败**，验证你会不会去归因（`A2 索引缺失`）而不是直接怪检索算法 |
| 2 | `L-004` 的 query 含 `/` | 验证特殊字符不会让查询构造崩溃 |
| 3 | `L-010` 是唯一的"可能真需要语义"的题 | **只有它支持 R2 判定**，5 条 natural 才是足量样本；这里只放 2 条是"跑通链路"的最小配置 |

**如果这 10 条跑出来 `exact` 桶不是接近满分，先别做 B 批——先去查实现。**

## ⚠️ 这份示例的诚实边界（真实评测集不能这么做）

1. **我知道答案在哪。** 造这 10 条时我是**先看了文件再写 query** 的。真实的评测集必须反过来：先有"我确实想知道答案"的问题，再去找答案。`EVAL.md` §2.9 陷阱 9 明确禁止从"已知答案"倒推问题。
2. **没做"参考解"校验。** `EVAL.md` §2.4 Step 6 的三道人工保险（写参考解 / 查是否抄了源词 / 留 holdout）**这里一条都没做**。真实评测集必须做。
3. **只覆盖一个仓库、一种语言（TypeScript）。** 真实评测集应该同时覆盖你最常用的语言。
4. **`expect_paths` 可能不完整。** 例如 `L-007` 只列了 `session/` 下的两个文件，但相关的测试文件、其他包的消费方也可能算"对"。**我们无法声称知道全部相关文件——这正是 ADR-12 把指标定为 `Success@k` 而不是 `Recall@k` 的原因。**
